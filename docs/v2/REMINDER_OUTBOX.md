# Reminder transport foundation

Decision: extend canonical commitments and the existing connection vault with a durable outbox. Planning: deep; context: queue, action, consent, erasure and database boundaries; delegation: none. Changes are reversible source edits and disposable tests. Migration 39 is not applied to any hosted database.

The primary failure is an external send that succeeds while its response is lost. Blind retry can send duplicates. The outbox separates queued, leased, dispatching, delivered, uncertain, failed and cancelled states. Only an expired lease that never reached dispatching can return to the queue. An expired dispatch is uncertain and cannot be automatically replayed. A matching lease token fences stale workers; a provider message ID is required to record delivery.

The default-off ASSISTANT_OUTBOX_ENABLED flag permits scheduling only a user's explicit Snooze with an existing linked channel and notification consent. The unique schedule key includes owner, canonical commitment, revision, channel and slot. No inferred local hour or catch-up schedule is created when preferences are enabled. Check-ins expire after 24 hours of delay. New actions or preference/revocation changes cancel queued/leased work. Every claim and dispatch preparation rechecks source revision/status, connection revision, preference version and active account.

Quiet hours are evaluated through real UTC instants in the owner's IANA timezone, including daylight-saving gaps and repeated hours. Leases reserve message capacity under the owner lock. Usage covers the full local day and at least the preceding 24 hours; uncertain/rejected attempts consume capacity conservatively. A quiet/capped item waits without claiming delivery.

There is deliberately no provider adapter, polling sender or Telegram callback handler in this slice. The outbox flag remains OFF. Existing UI still says delivery is not enabled. A future sender must commit dispatch intent, then re-enter an owner transaction, revalidate all gates immediately before sending and hold the owner/source/connection locks through the bounded provider call. Disable/revoke must serialize against that final authorization. It must never pass these records into the generic retrying job handler. An uncertain outcome requires explicit user-visible reconciliation; this implementation does not assume provider-side deduplication.

The outbox stores no message text or chat identifiers. Operational lease tokens are excluded from portable exports. Account erasure removes owner rows, and composite foreign keys reject cross-owner source/connection references. Direct browser roles cannot read or forge the outbox. No provider, real recipient or paid service is used in validation.

Local validation: 79 focused outbox/action/connection/account/schema/security checks passed before the final expiry and export/action regressions; the final outbox file passed all 18 cases. Ruff and mypy (178 source files) passed. The security scanner identified the schema type string for lease_token as a possible password; that exact field now has a narrow documented false-positive annotation. Four PostgreSQL cases cover concurrent schedule deduplication/cap reservations, stale source edits, persisted crash recovery and owner/browser isolation; execution is pending in disposable CI. These results do not verify a hosted migration, provider delivery or an enabled worker.
