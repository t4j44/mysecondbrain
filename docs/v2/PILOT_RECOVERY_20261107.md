The code did confirm a validation defect: an embedded URL password plus any separate password was rejected, even when both values matched. The shared connection validator now accepts matching values (including percent-encoded special characters), rejects conflicting values as `DATABASE_PASSWORD_CONFLICT`, pins direct/session connections to `rpkjmdrralzxhdsgceal`, and rejects transaction ports, spoofed hosts and target-overriding query options. The original owner failure is **not** attributed to this defect without additional evidence.

Failures now retain a safe `failure_stage` and specific validation `error_type`; credentials and raw exception messages are not recorded. Stages distinguish password/project/endpoint/passphrase validation, encryption, file save, final-file verification and independent verification. Receipt verification can be retried without a duplicate-property error.
