## Operator recovery procedure

1. Use the masked form to supply only the staging session/direct connection on port 5432 and a new 20+ character passphrase. Retain the passphrase in a password manager outside Google Drive. DPAPI is a local convenience, not independent key escrow.
2. Run `scripts/backup/staging_recovery.py` with the private setup path and private work directory. It pins the staging project, uses TLS certificate/hostname verification, forces read-only transactions, and holds a repeatable-read exported snapshot shared by the manifest and full custom dump. This is client-enforced read-only operation, not a newly provisioned least-privilege database role. It makes no hosted schema/account changes.
3. The encrypted archive includes the complete custom PostgreSQL dump plus the private comparison manifest. Only the authenticated encrypted `.enc` file may leave the private work directory. Plain custom dumps are removed in `finally`. Never upload setup files, passphrases, plaintext dumps, manifests, SQL/server errors or auth state to GitHub or Drive.
4. Upload the encrypted file to the separate private Drive recovery folder. Check owner-only permissions, cloud file size and checksum. Download the uploaded bytes into the private work directory; SHA-256 must equal the local encrypted file before proceeding. This read-back establishes that the cloud copy exists independently of local sync.
5. Run `scripts/restore/pilot_restore.py` against that downloaded encrypted copy, with the private setup, separate work directory, the private PG17 server distribution and PostgreSQL client directory. There is no remote/existing target parameter. The tool initializes a new cluster bound only to `127.0.0.1`, restores source roles with login disabled and without copying role passwords, installs matching extension versions, and compares the restored application/Auth/Storage/migration scope against the manifest.
6. Recovery stays BLOCKED/FAIL unless all comparison checks pass and cloud read-back/decryption is verified. An empty Storage object table is point-in-time evidence of no file bytes to copy; if future objects exist, separately export their bytes and hashes and test retrieval. Database metadata is not a Storage file backup.
7. Separately inventory Supabase Auth service settings: invite/signup controls, site/redirect allowlists, providers, SMTP, token settings and signing-key/secret recovery dependencies. Keep any secret material in the password manager, never the public report. Database Auth rows alone do not reconstruct a functioning Auth service. Complete this gate before declaring full recovery PASS.
8. After comparison, the tool stops and removes only its newly created local cluster and temporary plaintext extraction. A failed stop must block deletion. Review private leftovers after interrupted runs. Ordinary deletion on SSD/Windows cannot prove physical erasure; use encrypted local storage and minimize plaintext lifetime. Preserve only encrypted backups and sanitized evidence; clean the one-use input task when done.
